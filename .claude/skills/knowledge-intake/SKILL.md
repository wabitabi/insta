# 資料を knowledge/ に取り込む手順

## 1. 読めるか確認する
- 読めない資料は、ファイル名やURLと理由を一覧にする
  - 例：Instagramのリンクは、この環境からはアクセスできない
- 読めない資料について、必要な形式を本人に伝える
  - テロップやキャプション：テキスト（.md／.txt）
  - 画面：スクリーンショット（.png／.jpg）
  - 数字：CSV（`knowledge/metrics.md` の列）
- **読めなかった資料の中身を推測で書かない**

## 2. 分類する
資料の中の1文ごとに、次のどれかのラベルを付ける。
| ラベル | 基準 |
|---|---|
| 【継続】 | 本人が「いつも」「ルール」として明言したもの |
| 【好み】 | 本人の好みや、1本の実例から読み取った傾向。参考にするが強制しない |
| 【単発】 | 特定の投稿や、その回だけの指示 |
| 【提案】 | チームが決めた運用案。本人の承認待ち |
| 【仮説】 | 数字の根拠が無い「こうすると伸びる」という考え |
| 【要確認】 | 本人に確認が必要なもの |

- 実例は、原文、出典、採用理由、再現する要素、**流用しない固有名詞と数字**に分ける

## 3. 書き込む先
| 内容 | ファイル |
|---|---|
| 相手、目的、口調、価値、導線 | `knowledge/brand.md` |
| 本人の経験と使える範囲 | `knowledge/profile.md` |
| 良い実例 | `knowledge/good-examples.md` |
| NG例 | `knowledge/ng-examples.md` |
| 数字の定義、期間、比較 | `knowledge/metrics.md` |
| 字幕、素材、音声、カット、納品 | `knowledge/editing.md` |
| 頻度、素材の一覧、ツール | `knowledge/operations.md` |

- 書き込むたびに「最終更新」の日付と出典を書く
- 古い内容は消さない。置き換えるときは、変更した日付と理由を書く

## 4. 矛盾を見つけたら
- 新しい資料と古い資料が食い違う部分だけを抜き出し、**その部分だけ**本人に質問する
- 回答が来るまで、その項目は【要確認】にして、使わない側に倒す
  - 例：「無料」の範囲が食い違う → 確認できている「相談無料」だけを使う
- はっきりした変更の指示（例：週5本 → 週3本）は矛盾ではなく更新として扱い、日付を書く
