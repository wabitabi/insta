# 台本を書く手順

## 1. 読む（省略しない）
- `CLAUDE.md`
- `knowledge/brand.md`：相手、目的、口調、導線
- `knowledge/profile.md`：使ってよい経験の範囲
- `knowledge/good-examples.md`：再現する要素と、流用禁止のリスト
- `knowledge/ng-examples.md`：NG例
- `knowledge/editing.md` の「1. 字幕」
- 企画（`outputs/plans/`）と調査メモ（`outputs/research/`）。無ければ「未作成」と書く

## 2. 材料を分ける
台本に入れる情報を、次の3つに分けてメモする。
- **本人の経験**：`profile.md` に書いてあるものだけ
- **出典つきの事実**：調査メモにあるものだけ。出典と確認日を付ける
- **足りないもの**：`【本人の体験：未設定】` `【要確認】` として空欄にする。補って作らない

## 3. 書く
1. 冒頭（2秒）の案を3つ出し、1つに★を付ける
   - 「冒頭2秒で掴む」は【仮説】
2. 本編を字幕の単位で書く
   - 1画面1〜2行
   - 重要語が改行で割れないように
3. 熊本弁は軽く、現代風に（1本に1〜2か所まで）
4. 締めの呼びかけは1つ。DMの合言葉は投稿のテーマに合わせる
5. キャプションと、ハッシュタグ10個以内
6. 実例の固有名詞や数字を使っていないか、`good-examples.md` の流用禁止リストで確認する

## 4. 出力
`outputs/scripts/YYYY-MM-DD_テーマ.md`
```
# 台本：<テーマ>（形式／約◯秒）
- 対象の悩み（A〜H）/ 締めの呼びかけ / 使った本人の経験
## 冒頭の案（3つ、採用に★）
## 本編
| # | 秒 | 字幕（1〜2行） | ナレーション | 映像メモ |
## キャプション
## ハッシュタグ
## ルールの反映メモ（どのルールをどこに入れたか）
## 未設定・要確認
```

## 5. 終わる前の確認
- [ ] 作った経験や、出典の無い数字が無い
- [ ] 煽り、他国や他社を下げる表現、成果の保証、AI感の定型句が無い
- [ ] 「無料」と書いたのは相談だけ
- [ ] 字幕がすべて1〜2行
- [ ] 「未設定・要確認」の欄がある（無ければ「なし」と書く）
